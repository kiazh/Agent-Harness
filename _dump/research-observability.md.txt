15|## Executive Summary
16|
17|AgentHarness has **audit logging** (sanitized JSON events to stderr via the `ah.audit` logger, persisted asynchronously to the `audit_events` table) and **standard Python logging** (`logging.getLogger(__name__)`). This still falls short of production observability in the five key areas below:
18|
19|1. **No distributed tracing** — a single agent run fans out to 10–30+ LLM calls and tool executions with no causal chain.
20|2. **No metrics** — token counts, latency, cost, and success rates are logged but never aggregated.
21|3. **No structured log schema** — audit events are ad-hoc JSON with no consistent envelope.
22|4. **No cost tracking** — token usage is summed per run but never attributed per-model, per-session, or per-user.
23|5. **No alerting or dashboards** — there is no way to detect anomalies or visualize trends.
24|
25|This document maps industry best practices to AgentHarness's specific architecture and proposes a phased adoption plan.

29|## 1. Structured Logging
30|
31|### Current State
32|
33|AgentHarness has structured logging plus a durable, sanitized audit trail:
34|
35|```python
36|# ah/core/provider.py — audit logger (JSON lines to stderr, plus persistence)
37|_audit_logger = logging.getLogger("ah.audit")
38|def audit_log(event_type: str, **kwargs) -> None:
39|    entry = {"timestamp": time.time(), "event": event_type, **kwargs}
40|    _audit_logger.info(json.dumps(entry, default=str))
41|
42|# ah/core/agent.py — standard library logging
43|logger = logging.getLogger(__name__)
44|logger.warning("LLM call failed (attempt %d/%d): %s — retrying in %ds", ...)
45|```
46|
47|**What works:** The audit logger already emits JSON with `event_type` and `session_id`. This is the right instinct.
48|
49|**What's missing:**
50|- No consistent envelope (every call site invents its own fields).
51|- No `trace_id` / `span_id` correlation.
52|- No log levels for audit events (everything is INFO).
53|- No PII redaction — `tool_args` and `result_preview` are logged verbatim.
54|- No output destination — stderr + DB only, no file rotation, no log shipping.
55|
56|### Industry Standard: The Log Envelope
57|
58|Production agent systems use a **structured log envelope** — a consistent JSON schema for every log event:
59|
60|```json
61|{
62|  "timestamp": "2026-10-01T15:30:00.123Z",
63|  "level": "info",
64|  "trace_id": "tr_8f3a2b1c",
65|  "span_id": "st_001",
66|  "agent_id": "harness",
67|  "session_id": "sess_abc123",
68|  "event_type": "tool_call",
69|  "tool": "web_search",
70|  "duration_ms": 342,
71|  "status": "success",
72|  "tokens": {"input": 1243, "output": 87},
73|  "cost_usd": 0.0024,
74|  "model": "claude-sonnet-4-6"
75|}
76|```
77|
78|**Required fields for AgentHarness:**
79|
80|| Field | Type | Description |
81||-------|------|-------------|
82|| `timestamp` | ISO-8601 | Event time with millisecond precision |
83|| `level` | string | `debug`, `info`, `warning`, `error` |
84|| `trace_id` | string | Unique ID for the entire agent run |
85|| `span_id` | string | Unique ID for this specific step |
86|| `agent_id` | string | Which agent is executing |
87|| `session_id` | string | Which session this belongs to |
88|| `event_type` | string | `llm_call`, `tool_call`, `decision`, `error`, `completion` |
89|| `duration_ms` | int | Wall-clock duration of this step |
90|| `status` | string | `success`, `error`, `timeout`, `retry` |
91|
92|**Recommended fields:**
93|
94|| Field | Type | Description |
95||-------|------|-------------|
96|| `model` | string | LLM model identifier |
97|| `tokens_in` | int | Input tokens for this call |
98|| `tokens_out` | int | Output tokens for this call |
99|| `cost_usd` | float | Estimated cost in USD |
100|| `tool_name` | string | Tool name (if event_type is tool_call) |
101|| `tool_input_hash` | string | SHA-256 of tool input (for deduplication without PII) |
102|| `retry_count` | int | How many times this step was retried |
103|| `parent_span_id` | string | For nested agent calls |
104|
105|### PII Redaction
106|
107|AgentHarness logs `tool_args` and `result_preview` verbatim. In production, these contain user data, API keys, and PII. The industry standard is:
108|
109|1. **Hash identifiers** — replace user IDs, session IDs with HMAC hashes.
110|2. **Truncate content** — log first 200 chars, hash the rest.
111|3. **Redact patterns** — regex-based redaction for emails, phone numbers, API keys, credit cards.
112|4. **TTL-based retention** — full prompts stored for 7 days, aggregated metrics for 30 days.
113|
114|### Proposed Implementation for AgentHarness
115|
116|```python
117|# ah/observability/logging.py
118|import hashlib
119|import json
120|import logging
121|import re
122|import time
123|import uuid
124|from typing import Any
125|
126|class StructuredLogger:
127|    """Consistent log envelope for all agent events."""
128|    
129|    def __init__(self, agent_id: str, session_id: str, trace_id: str | None = None):
130|        self.agent_id = agent_id
131|        self.session_id = session_id
132|        self.trace_id = trace_id or f"tr_{uuid.uuid4().hex[:16]}"
133|        self._span_counter = 0
134|    
135|    def _next_span_id(self) -> str:
136|        self._span_counter += 1
137|        return f"st_{self._span_counter:04d}"
138|    
139|    def log(self, event_type: str, level: str = "info", **kwargs) -> dict:
140|        entry = {
141|            "timestamp": time.strftime("%Y-%m-%dT%H:%M:%S.%f", time.gmtime())[:-3] + "Z",
142|            "level": level,
143|            "trace_id": self.trace_id,
144|            "span_id": self._next_span_id(),
145|            "agent_id": self.agent_id,
146|            "session_id": self.session_id,
147|            "event_type": event_type,
148|            **kwargs,
149|        }
150|        _audit_logger.log(getattr(logging, level.upper()), json.dumps(entry, default=str))
151|        return entry
152|    
153|    def llm_call(self, model: str, tokens_in: int, tokens_out: int, 
154|                 duration_ms: int, status: str, cost_usd: float = 0.0) -> dict:
155|        return self.log("llm_call", model=model, tokens_in=tokens_in, 
156|                       tokens_out=tokens_out, duration_ms=duration_ms, 
157|                       status=status, cost_usd=cost_usd)
158|    
159|    def tool_call(self, tool_name: str, duration_ms: int, status: str,
160|                  tool_input_hash: str = "") -> dict:
161|        return self.log("tool_call", tool=tool_name, duration_ms=duration_ms,
162|                       status=status, tool_input_hash=tool_input_hash)
163|```

167|## 2. Metrics
168|
169|### Current State
170|
171|AgentHarness aggregates in-process metrics (`ah/core/metrics.py`) and exposes them as Prometheus text at `/metrics`, including per-operation latency, counters, error rates, and token totals. Open questions remain around histograms over long windows and cross-restart aggregation.
172|
173|- What is the p95 latency for a tool call?
174|- Which model costs the most per session?
175|- What is the tool failure rate over the last hour?
176|- How many sessions hit the token budget?
177|
178|### Industry Standard: The Six Metric Categories
179|
180|Production agent systems track six categories of metrics:
181|
182|#### 2.1 Cost Metrics
183|
184|| Metric | Type | Description |
185||--------|------|-------------|
186|| `agent.cost.total` | Histogram | Total cost per agent run (USD) |
187|| `agent.cost.by_model` | Counter | Cost attributed per LLM model |
188|| `agent.cost.by_session` | Counter | Cost attributed per session |
189|| `agent.tokens.total` | Histogram | Total tokens per agent run |
190|| `agent.tokens.input` | Histogram | Input tokens per LLM call |
191|| `agent.tokens.output` | Histogram | Output tokens per LLM call |
192|| `agent.tokens.cache_hit` | Counter | Cache hit tokens (if using prompt caching) |
193|
194|#### 2.2 Performance Metrics
195|
196|| Metric | Type | Description |
197||--------|------|-------------|
198|| `agent.latency.e2e` | Histogram | End-to-end agent run latency |
199|| `agent.latency.llm` | Histogram | Per-LLM-call latency |
200|| `agent.latency.tool` | Histogram | Per-tool-call latency |
201|| `agent.latency.ttft` | Histogram | Time to first token (streaming) |

204|#### 2.3 Reliability Metrics
205|
206|| Metric | Type | Description |
207||--------|------|-------------|
208|| `agent.errors.total` | Counter | Total errors by type |

216|
217|| Metric | Type | Description |

219|| `agent.tool_success_rate` | Gauge | Percentage of tool calls that succeed |

222|| `agent.loop_detected` | Counter | Runs where the same tool was called with the same args 3+ times |

225|
226|| Metric | Type | Description |
227||--------|------|-------------|

229|| `agent.human_escalation_rate` | Gauge | Percentage of runs requiring human intervention |
230|| `agent.session_count` | Counter | Active sessions |
231|| `agent.user_satisfaction` | Gauge | Thumbs up/down ratio |
232|
233|#### 2.6 Token Usage Analytics
234|
235|| Metric | Type | Description |
236||--------|------|-------------|
237|| `agent.tokens.per_session` | Histogram | Total tokens consumed per session |
238|| `agent.tokens.per_run` | Histogram | Total tokens consumed per run |
239|| `agent.tokens.by_tool` | Counter | Tokens consumed by tool results |
240|| `agent.tokens.by_context` | Counter | Tokens consumed by context assembly |
241|| `agent.tokens.efficiency` | Gauge | Output tokens / input tokens ratio |

294|## 3. Tracing
295|
296|### Current State
297|
298|AgentHarness has OpenTelemetry spans around agent runs and tool calls when an SDK is configured. A single `ReActAgent.run()` call fans out to:
299|- 1 session lookup
300|- 1 context retrieval
301|- 1 prompt assembly
302|- N LLM calls (with retries)
303|- M tool executions
304|- N context chunk insertions
305|
306|All of these are correlated only by `session_id` in audit logs. There is no causal chain, no parent-child relationship, no way to reconstruct the execution tree.
307|
308|### Industry Standard: OpenTelemetry GenAI Semantic Conventions
309|
310|The OpenTelemetry community has defined **GenAI semantic conventions** (stable in 2024–2025) that standardize span attributes for LLM calls:
311|
312|| Attribute | Description |
313||-----------|-------------|
314|| `gen_ai.system` | Provider name (`openai`, `anthropic`, `openrouter`) |
315|| `gen_ai.request.model` | Model identifier |
316|| `gen_ai.request.temperature` | Temperature parameter |
317|| `gen_ai.request.max_tokens` | Max tokens parameter |
318|| `gen_ai.usage.input_tokens` | Input token count |
319|| `gen_ai.usage.output_tokens` | Output token count |
320|| `gen_ai.response.finish_reason` | `stop`, `length`, `tool_calls`, `content_filter` |
321|| `gen_ai.response.tool_calls` | Tool calls requested by the model |
322|| `gen_ai.agent.name` | Agent identifier |
323|| `gen_ai.session.id` | Session identifier |
324|
325|### What a Good Agent Trace Looks Like
326|
327|```
328|User Request (trace_id: tr_8f3a2b1c)
329|├── Orchestrator Agent (span: 4200ms)
330|│   ├── LLM Planning Call (span: 1100ms, tokens: 450 in / 87 out)
331|│   ├── Research Agent (span: 2800ms)
332|│   │   ├── LLM Call (span: 800ms, tokens: 2100 in / 340 out)
333|│   │   ├── Web Search Tool (span: 1200ms)
334|│   │   └── LLM Summarization (span: 600ms, tokens: 1800 in / 200 out)
335|│   └── LLM Final Response (span: 900ms, tokens: 680 in / 150 out)
336|└── Response Delivered (total: 4200ms, total_tokens: 5030)
337|```
338|
339|### Proposed Implementation for AgentHarness
340|
341|AgentHarness should instrument the ReAct loop with OpenTelemetry spans:
342|
343|```python
344|# ah/observability/tracing.py
345|from opentelemetry import trace
346|from opentelemetry.sdk.trace import TracerProvider
347|from opentelemetry.sdk.trace.export import BatchSpanProcessor
348|from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
349|
350|# Initialize once at startup
351|provider = TracerProvider()
352|provider.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
353|trace.set_tracer_provider(provider)
354|
355|tracer = trace.get_tracer("agent_harness")
356|
357|# In ReActAgent.run():
358|async def run(self, session_id, user_message, verbose=True):
359|    with tracer.start_as_current_span("agent.run") as root_span:
360|        root_span.set_attribute("gen_ai.agent.name", self.agent_id)
361|        root_span.set_attribute("gen_ai.session.id", str(session_id))
362|        root_span.set_attribute("agent.max_iterations", self.max_iterations)
363|        
364|        for iteration in range(self.max_iterations):
365|            with tracer.start_as_current_span(f"llm.call[{iteration}]") as llm_span:
366|                llm_span.set_attribute("gen_ai.request.model", self.provider.model)
367|                llm_span.set_attribute("gen_ai.request.temperature", 0.7)
368|                
369|                response = await self._call_llm_with_retry(messages, tools)
370|                
371|                llm_span.set_attribute("gen_ai.usage.input_tokens", 
372|                                       response.usage.get("prompt_tokens", 0))
373|                llm_span.set_attribute("gen_ai.usage.output_tokens", 
374|                                       response.usage.get("completion_tokens", 0))
375|                llm_span.set_attribute("gen_ai.response.finish_reason", 
376|                                       response.raw.get("choices", [{}])[0].get("finish_reason", "unknown"))
377|            
378|            for tc in response.tool_calls:
379|                with tracer.start_as_current_span(f"tool.{tc['function']['name']}") as tool_span:
380|                    tool_span.set_attribute("tool.name", tc["function"]["name"])
381|                    tool_span.set_attribute("tool.args", json.dumps(tool_args))
382|                    
383|                    result = await registry.execute(tool_name, **tool_args)
384|                    
385|                    tool_span.set_attribute("tool.result_preview", str(result)[:200])
386|                    tool_span.set_attribute("tool.duration_ms", duration_ms)
387|```

392|
393|### Current State
394|
395|AgentHarness has **no dashboards**. Metrics are exposed as Prometheus text; audit events persist to PostgreSQL.
396|
397|### Industry Standard: The Three-Layer Dashboard
398|
399|Production agent systems use a three-layer dashboard architecture:
400|
401|#### Layer 1: Business KPIs (Executive View)
402|
403|| Panel | Metric | Target |
404||-------|--------|--------|
405|| Task completion rate | `agent.task_completion_rate` | > 95% |
406|| Average task duration | `agent.latency.e2e` (p50) | < 60s |
407|| Cost per task | `agent.cost.total` (p50) | < $0.15 |
408|| User satisfaction | `agent.user_satisfaction` | > 4.0/5.0 |
409|
410|#### Layer 2: System Health (Engineering View)
411|
412|| Panel | Metric | Alert Threshold |
413||-------|--------|-----------------|
414|| Success rate by agent | `agent.task_completion_rate` by `agent_id` | < 90% |
415|| Failure rate by tool | `agent.errors.total` by `tool_name` | > 5% |
416|| Token usage trend | `agent.tokens.total` over time | > 2x baseline |
417|| Cost trend | `agent.cost.total` over time | > 1.5x baseline |
418|| Latency percentiles | `agent.latency.e2e` p50/p95/p99 | p99 > 5x p50 |
419|
420|#### Layer 3: Cost and Resources (Finance View)
421|
422|| Panel | Metric | Description |
423||-------|--------|-------------|

425|| Cost by model | `agent.cost.by_model` | Which models cost the most |

462|## 5. Alerting
463|
464|### Current State
465|
466|AgentHarness has **no alerting**. Errors are recorded in metrics and persisted audit events.
467|
468|### Industry Standard: The Three-Tier Alert Framework
469|
470|Production agent systems use a three-tier alert framework:
471|
472|#### Tier 1: Critical — Immediate Response (PagerDuty/Opsgenie)
473|
474|| Alert | Condition | Response |
475||-------|-----------|----------|
476|| Agent error rate spike | `agent.errors.total` > 10% (5-min avg) | Page on-call |
477|| Cost budget exceeded | `agent.cost.total` > 200% of hourly budget | Page on-call |
478|| Tool failure storm | Specific tool fails 3x consecutively in 5 min | Page on-call |
479|| Agent loop detected | Same tool called with same args 3+ times | Page on-call |
480|
481|#### Tier 2: Warning — Daily Review (Slack)
482|
483|| Alert | Condition | Response |
484||-------|-----------|----------|
485|| Agent success rate drop | `agent.task_completion_rate` drops > 5% vs previous day | Slack notification |
486|| Latency increase | `agent.latency.e2e` p95 increases > 50% from baseline | Slack notification |
487|| New error type | Unseen `error_type` in last 24 hours | Slack notification |
488|| Token usage spike | `agent.tokens.total` > 3x baseline | Slack notification |
489|
490|#### Tier 3: Info — Weekly Report (Email)
491|
492|| Alert | Condition | Response |
493||-------|-----------|----------|
494|| Cost trend | `agent.cost.total` trending up over 7 days | Weekly email |
495|| Usage pattern shift | New tool usage patterns detected | Weekly email |
496|| Prompt efficiency change | `agent.tokens.efficiency` changing over time | Weekly email |
497|
498|### The 4% Silent Failure Rule
499|
500|Research shows that if an agent's silent failure rate is under 4%, it won't show up in customer complaints. Between 1% and 4% is the danger zone — most teams are there and don't know it. **Outcome metrics** (task completion rate, correction rate) are the only way to detect this.
501|
502|### Proposed Implementation for AgentHarness
503|
504|```python
505|# ah/observability/alerting.py
506|from dataclasses import dataclass
507|from typing import Callable
508|
509|@dataclass
510|class AlertRule:
511|    name: str
512|    condition: Callable[[dict], bool]
513|    severity: str  # "critical", "warning", "info"
514|    cooldown_minutes: int = 10
515|
516|ALERT_RULES = [
517|    AlertRule(
518|        name="agent_error_rate_spike",
519|        condition=lambda m: m.get("error_rate_5m", 0) > 0.10,
520|        severity="critical",
521|    ),
522|    AlertRule(
523|        name="cost_budget_exceeded",
524|        condition=lambda m: m.get("hourly_cost", 0) > m.get("hourly_budget", 10.0) * 2,
525|        severity="critical",
526|    ),
527|    AlertRule(
528|        name="agent_loop_detected",
529|        condition=lambda m: m.get("max_loop_count", 0) > 3,
530|        severity="critical",
531|    ),
532|    AlertRule(
533|        name="success_rate_drop",
534|        condition=lambda m: m.get("success_rate", 1.0) < m.get("baseline_success_rate", 0.95) * 0.95,
535|        severity="warning",
536|    ),
537|    AlertRule(

547|## 6. Cost Tracking
548|
549|### Current State
550|
551|AgentHarness tracks `total_tokens` per run and durable per-session/per-agent usage in `llm_usage`, but does **not** calculate dollar cost. The `LLMResponse.usage` dict contains token counts but no cost estimation.
552|
553|### Industry Standard: Per-Span Cost Attribution
554|
555|Production agent systems track cost at multiple granularities:
556|
557|| Level | What to Track | Why |
558||-------|---------------|-----|
559|| Per LLM call | `cost_usd = (input_tokens × input_price) + (output_tokens × output_price)` | Identify expensive calls |
560|| Per tool call | `cost_usd = (tool_result_tokens × input_price)` | Identify expensive tools |
561|| Per agent run | `sum(all LLM call costs)` | Budget per task |
562|| Per session | `sum(all run costs)` | Budget per user session |
563|| Per user | `sum(all session costs)` | Budget per user |
564|| Per model | `sum(all costs for model)` | Model selection optimization |
565|
566|### Pricing Table (Example)

576|
577|```python
578|# ah/observability/cost.py
579|from dataclasses import dataclass
580|
581|# Pricing table — update regularly
582|MODEL_PRICING = {
583|    "anthropic/claude-3.5-sonnet": {"input": 3.00, "output": 15.00},
584|    "anthropic/claude-3-haiku": {"input": 0.25, "output": 1.25},
585|    "openai/gpt-4o": {"input": 2.50, "output": 10.00},
586|    "openai/gpt-4o-mini": {"input": 0.15, "output": 0.60},
587|}
588|
589|def estimate_cost(model: str, input_tokens: int, output_tokens: int) -> float:
590|    """Estimate cost in USD for an LLM call."""
591|    pricing = MODEL_PRICING.get(model, {"input": 0.0, "output": 0.0})
592|    return (input_tokens * pricing["input"] + output_tokens * pricing["output"]) / 1_000_000
593|
594|# In LLMProvider.complete():
595|async def complete(self, messages, model=None, ...):
596|    response = await self._make_request(messages, model, ...)
597|    
598|    # Calculate cost
599|    cost = estimate_cost(
600|        model or self.model,
601|        response.usage.get("prompt_tokens", 0),
602|        response.usage.get("completion_tokens", 0),
603|    )
604|    
605|    # Add cost to response
606|    response.cost_usd = cost
607|    
608|    return response
609|```

613|## 7. Token Usage Analytics
614|
615|### Current State
616|
617|AgentHarness tracks `total_tokens` per run, durable `llm_usage`, and stores `token_count` per context chunk, but has **no token analytics** — no breakdown by component, no trend analysis, no efficiency metrics.
618|
619|### Industry Standard: Token Flow Analysis
620|
621|A typical agent run consumes tokens in four stages:
622|
623|```
624|User Input (100 tokens)
625|    ↓
626|Context Assembly (2,000 tokens) ← retrieved chunks + recent context
627|    ↓
628|LLM Call (2,100 in → 500 out) ← prompt + response
629|    ↓
630|Tool Execution (0 tokens) ← tool calls don't consume tokens directly
631|    ↓
632|Tool Result (1,000 tokens) ← tool output added to context
633|    ↓
634|Next LLM Call (3,100 in → 500 out) ← accumulated context
635|    ↓
636|Final Response (500 tokens)
637|```
638|
639|**Total: 5,700 input tokens, 1,000 output tokens**
640|
641|### Key Token Analytics
642|
643|| Metric | Description | Why It Matters |
644||--------|-------------|----------------|
645|| `tokens.per.run` | Total tokens per agent run | Cost tracking |
646|| `tokens.per.session` | Total tokens per session | Session budget |
647|| `tokens.by.context` | Tokens consumed by context assembly | Context efficiency |
648|| `tokens.by.tool_results` | Tokens consumed by tool results | Tool output size |
649|| `tokens.by.system_prompt` | Tokens consumed by system prompt | Prompt optimization |
650|| `tokens.efficiency` | Output / input ratio | Agent effectiveness |
651|| `tokens.wasted` | Tokens from truncated or irrelevant context | Context quality |
652|
653|### The Token Budget Problem
654|
655|AgentHarness has `MAX_TOKEN_BUDGET = 50_000` and `context_budget = 8000` per session. But there is no tracking of:
656|- How often the budget is exceeded
657|- Which component consumes the most tokens
658|- Whether the budget is appropriate for the task
659|
660|### Proposed Implementation for AgentHarness
661|
662|```python
663|# ah/observability/tokens.py
664|@dataclass
665|class TokenBreakdown:
666|    """Token usage breakdown for a single agent run."""
667|    user_input: int = 0
668|    system_prompt: int = 0
669|    context_assembly: int = 0
670|    llm_input: int = 0
671|    llm_output: int = 0
672|    tool_results: int = 0
673|    total: int = 0
674|    
675|    @property
676|    def efficiency(self) -> float:
677|        """Output / input ratio."""
678|        return self.llm_output / max(self.llm_input, 1)
679|    
680|    @property
681|    def context_overhead(self) -> float:
682|        """Context tokens / total input tokens."""
683|        return (self.context_assembly + self.tool_results) / max(self.llm_input, 1)
684|
685|# In ReActAgent.run():
686|token_breakdown = TokenBreakdown(
687|    user_input=get_token_count(user_message),
688|    system_prompt=get_token_count(self.system_prompt),
689|    context_assembly=sum(c.token_count for c in recent),
690|)
691|
692|# After each LLM call:
693|token_breakdown.llm_input += response.usage.get("prompt_tokens", 0)
694|token_breakdown.llm_output += response.usage.get("completion_tokens", 0)
695|
696|# After each tool call:
697|token_breakdown.tool_results += len(result_str) // 4
698|
699|# At end of run:
700|token_breakdown.total = token_breakdown.llm_input + token_breakdown.llm_output
701|```

784|## 10. Key Takeaways
785|
786|1. **Observability is not optional for production agents.** Without it, you cannot debug, improve, or trust your agents.
787|
788|2. **The three pillars (metrics, traces, logs) still apply**, but LLM workloads need token-level cost dimensions, TTFT separated from total latency, and alerts on p99 and tail-shape ratios.
789|
790|3. **OpenTelemetry GenAI semantic conventions** are the open standard. Instrumenting against them keeps you portable across backends.
791|
792|4. **Cost tracking is the highest-ROI observability investment.** A single runaway agent loop can cost $10 in a minute. Token-level cost attribution catches this immediately.
793|
794|5. **The 4% silent failure rule** means you need outcome metrics (task completion rate, correction rate), not just infrastructure metrics (latency, error rate).
795|
796|6. **Start with structured logging and cost tracking.** This takes 2–3 days and gives you 80% of the value. Add tracing and dashboards incrementally.
797|
798|7. **AgentHarness's audit logger is a good foundation.** It already emits JSON with `event_type` and `session_id`. The gap is consistency, correlation, and aggregation — not a rewrite.
