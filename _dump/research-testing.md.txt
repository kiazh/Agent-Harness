31|## 1. Executive Summary
32|
33|Production testing for an AI agent framework differs fundamentally from traditional software testing. The system under test is **non-deterministic** (LLM outputs vary), **stateful** (conversations accumulate context), and **multi-component** (agent loop + tools + providers + database + skills). A robust test strategy must account for all three properties.
34|
35|**Key findings from industry research:**
36|
37|- **95% of tests should use mocked LLM responses** — real API calls are slow, expensive, and non-deterministic. Only a thin layer of E2E smoke tests should hit real APIs. ([OpenHelm, 2024](https://openhelm.ai/blog/agent-testing-strategies-unit-integration-e2e))
38|- **The test pyramid inverts for agents** — unit tests are fast and deterministic but can't verify agent behavior; E2E tests verify behavior but are slow and flaky. The sweet spot is **integration tests with mocked LLM + real tools + real database**. ([Zylos Research, 2026](https://zylos.ai/research/2026-05-07-ai-agent-testing-strategies-production-validation/))
39|- **Property-based testing is underutilized** — Hypothesis-style testing can find edge cases in prompt assembly, tool argument parsing, and context management that example-based tests miss. ([PBT-Bench, 2026](https://arxiv.org/abs/2605.15229))
40|- **Chaos engineering is essential** — LLM agents fail in production not from bugs but from unexpected inputs, tool failures, and context overflow. Chaos testing validates recovery paths. ([Owotogbe, 2025](https://arxiv.org/abs/2505.03096))
41|- **Load testing must simulate conversation dynamics** — traditional request/response load testing misses the "context avalanche" where long conversations degrade performance. ([The New Stack, 2026](https://thenewstack.io/why-load-tests-lie-harsh-truth-about-ai-agent-performance))

45|## 2. The Agent Testing Pyramid
46|
47|### 2.1 Classical Pyramid vs Agent Pyramid
48|
49|```
50|Classical:                    Agent:
51|                             
52|    E2E (few)                    Production Monitors (synthetic probes)
53|   Integration (some)          E2E / Behavioral (did agent achieve goal?)
54|  Unit (many)                 Integration (tool-call sequences, state transitions)
55|                              Component (parsers, routers, tool wrappers)
56|                             Unit (pure functions, schema inference)
57|```
58|
59|The agent pyramid adds two layers:
60|- **Component tests** — between unit and integration; test individual agent components (PromptAssembler, ToolRegistry, SkillParser) in isolation with mocked dependencies.
61|- **Production monitors** — above E2E; continuous synthetic probes that run against production to detect regressions.
62|
63|### 2.2 Recommended Distribution for AgentHarness
64|
65|| Layer | Count | Run Frequency | LLM Mocked? | DB | Tools | Duration |
66||-------|-------|---------------|-------------|-----|-------|----------|
67|| Unit | ~200 | Every commit | N/A (no LLM) | Mocked | Real | <5s |
68|| Component | ~50 | Every commit | Yes (stub) | Mocked | Real | <10s |
69|| Integration | ~50 | Every PR | Yes (fake) | Real (testcontainer) | Real | <2min |
70|| E2E | ~10 | Nightly | Real or LLM-as-judge | Real | Real | <10min |
71|| Chaos | ~20 | Weekly | Yes (fault injection) | Real | Real | <30min |
72|| Load | ~5 | Pre-release | Yes (mocked) | Real | Real | <1hr |

108|### 3.4 Recommended Unit Test Patterns
109|
110|```python
111|# Pattern 1: Parametrized edge cases
112|@pytest.mark.parametrize("input_text,expected_min,expected_max", [
113|    ("", 0, 0),
114|    ("a", 1, 1),
115|    ("hello world", 2, 3),
116|    ("x" * 400, 99, 101),
117|    ("你好世界", 1, 4),
118|])
119|def test_estimate_tokens_bounds(input_text, expected_min, expected_max):
120|    assembler = PromptAssembler()
121|    tokens = assembler._estimate_tokens(input_text)
122|    assert expected_min <= tokens <= expected_max
123|
124|# Pattern 2: Round-trip serialization
125|def test_msgpack_roundtrip():
126|    payload = {"content": "hello", "nested": {"key": [1, 2, 3]}}
127|    packed = msgpack.packb(payload, use_bin_type=True)
128|    unpacked = msgpack.unpackb(packed, raw=False)
129|    assert unpacked == payload
130|
131|# Pattern 3: Schema inference properties
132|def test_infer_schema_preserves_all_params():
133|    def func(a: str, b: int, c: float = 1.0, d: bool = True) -> str:
134|        return "ok"
135|    schema = ToolRegistry()._infer_schema(func)
136|    assert set(schema["properties"].keys()) == {"a", "b", "c", "d"}
137|    assert set(schema["required"]) == {"a", "b"}
138|```

142|## 4. Integration Testing
143|
144|### 4.1 What to Test
145|
146|Integration tests verify **component interactions** with real dependencies where feasible:
147|
148|- **Agent loop + real tools** — mock only the LLM provider, use real `ToolRegistry` with real file/terminal tools
149|- **Agent loop + real database** — use `testcontainers-python` to spin up PostgreSQL, test actual SQL queries
150|- **Provider + HTTP mocking** — mock `httpx.AsyncClient` at the transport level, test full request/response cycle
151|- **Session + Context + Agent** — test the full flow: create session → add chunks → run agent → verify context updated

228|## 5. End-to-End Testing
229|
230|### 5.1 What to Test
231|
232|E2E tests verify **complete user workflows** through the CLI or API:
233|
234|- **CLI workflow** — `agent-harness chat "message"` → agent responds correctly
235|- **Multi-turn conversation** — context accumulates across turns
236|- **Skill activation** — skill triggers on relevant queries
237|- **Error recovery** — agent recovers from tool failures, malformed LLM responses
238|- **Session persistence** — sessions survive restart, context is retrievable
239|
240|### 5.2 LLM-as-Judge Pattern
241|
242|For E2E tests, exact string matching is insufficient because LLM outputs vary. Use **LLM-as-judge** or **behavioral assertions**:
243|
244|```python
245|async def test_agent_answers_question():
246|    """E2E test with behavioral assertion."""
247|    agent = ReActAgent(provider=get_provider(), max_iterations=5)
248|    response = await agent.run(session_id, "What is 2+2?")
249|    
250|    # Behavioral assertion, not exact match
251|    assert response.content is not None
252|    assert len(response.content) > 0
253|    assert "4" in response.content  # Correct answer present
254|    
255|    # LLM-as-judge (optional, for subjective quality)
256|    judge_prompt = f"Does this answer correctly respond to 'What is 2+2'? Answer: {response.content}"
257|    judge_response = await provider.complete([{"role": "user", "content": judge_prompt}])
258|    assert "yes" in judge_response.content.lower()
259|```
260|
261|### 5.3 E2E Test Matrix
262|
263|| Scenario | LLM | DB | Tools | Assertion |
264||----------|-----|-----|-------|-----------|
265|| Simple Q&A | Real | Real | None | Answer contains expected fact |
266|| File read | Real | Real | read_file | File content in response |
267|| Multi-tool | Real | Real | read_file + write_file | Both tools executed |
268|| Error recovery | Real | Real | failing tool | Agent reports error gracefully |
269|| Skill activation | Real | Real | skill content | Skill content in prompt |
270|| Session continuity | Real | Real | None | Context from turn 1 in turn 2 |
271|| Max iterations | Real | Real | None | Graceful termination |
272|| Token budget | Real | Real | None | Budget not exceeded |
273|
274|### 5.4 Current State
275|
276|AgentHarness has **zero true E2E tests**. The CLI tests use `CliRunner` but mock the database and session manager. No test exercises the full `chat` command with a real agent loop.

280|## 6. LLM Mocking Strategies
281|
282|### 6.1 The Five Test Doubles for LLM
283|
284|Following Martin Fowler's taxonomy ([Test Double](https://martinfowler.com/bliki/TestDouble.html)):
285|
286|| Double | Use Case | Example |
287||--------|----------|---------|
288|| **Dummy** | Fill parameter lists, never used | `LLMResponse(content="")` for tests that don't check LLM output |
289|| **Stub** | Return canned responses | `provider.complete = AsyncMock(return_value=LLMResponse(content="test"))` |
290|| **Fake** | Working implementation, simplified | `FakeProvider` that returns predetermined responses based on input patterns |
291|| **Spy** | Record calls for verification | `SpyProvider` that wraps real provider and records all calls |
292|| **Mock** | Pre-programmed expectations | `mock_provider.complete.assert_called_with(messages=...)` |
293|
294|### 6.2 Recommended: FakeProvider Pattern
295|
296|```python
297|class FakeProvider(LLMProvider):
298|    """Deterministic provider for testing — no API calls."""
299|    
300|    def __init__(self, responses: list[LLMResponse]):
301|        self.responses = responses
302|        self.call_count = 0
303|        self.calls: list[dict] = []
304|    
305|    async def complete(self, messages, **kwargs) -> LLMResponse:
306|        self.calls.append({"messages": messages, "kwargs": kwargs})
307|        if self.call_count >= len(self.responses):
308|            raise RuntimeError("FakeProvider ran out of responses")
309|        response = self.responses[self.call_count]
310|        self.call_count += 1
311|        return response
312|    
313|    async def stream_complete(self, messages, **kwargs):
314|        response = await self.complete(messages, **kwargs)
315|        yield StreamEvent(type="text", content=response.content)
316|        yield StreamEvent(type="done", response=response)
317|    
318|    async def embed(self, text: str) -> list[float]:
319|        return [0.1] * 1536  # Dummy embedding
320|```
321|
322|### 6.3 Mocking at the Right Level
323|
324|**Don't mock too high** (mocking the agent loop itself):
325|```python
326|# BAD: Tests nothing about the agent
327|with patch("ah.core.agent.ReActAgent.run") as mock_run:
328|    mock_run.return_value = AgentResponse(content="test")
329|    # This tests that the mock was called, not that the agent works
330|```
331|
332|**Don't mock too low** (mocking `json.loads`):
333|```python
334|# BAD: Tests that json.loads was called, not that the agent handles JSON
335|with patch("json.loads") as mock_loads:
336|    mock_loads.return_value = {"path": "/tmp/test"}
337|    # This tests the mock, not the agent
338|```
339|
340|**Do mock at the provider boundary**:
341|```python
342|# GOOD: Mock only the LLM, test everything else for real
343|provider = FakeProvider([
344|    LLMResponse(content="", tool_calls=[...]),
345|    LLMResponse(content="final answer"),
346|])
347|agent = ReActAgent(provider=provider, max_iterations=5)
348|response = await agent.run(session_id, "test")
349|# Now verify the agent actually executed the tool, stored context, etc.
350|```
351|
352|### 6.4 Mocking HTTP for Provider Tests
353|
354|```python
355|@pytest.fixture
356|def mock_httpx():
357|    """Mock httpx at the transport level."""
358|    with patch("httpx.AsyncClient") as mock_client_cls:
359|        mock_client = AsyncMock()
360|        mock_client_cls.return_value = mock_client

367|        }
368|        mock_response.raise_for_status = MagicMock()
369|        mock_client.post = AsyncMock(return_value=mock_response)
370|        
371|        yield mock_client
372|```

380|## 7. Property-Based Testing
381|
382|### 7.1 Why Property-Based Testing for Agents
383|
384|Property-based testing (PBT) generates hundreds of random inputs to verify **invariants** — properties that should hold for all inputs. This is especially valuable for agent frameworks because:
385|
386|- **Prompt assembly** should never produce empty prompts, regardless of input
387|- **Token estimation** should always be positive and monotonic (longer text → more tokens)
388|- **Tool schema inference** should always produce valid JSON Schema
389|- **Context compression** should never exceed the original size
390|- **Agent loop** should always terminate (no infinite loops)
391|
392|### 7.2 Hypothesis for AgentHarness
393|
394|```python
395|from hypothesis import given, strategies as st, settings
396|
397|class TestPromptAssemblerProperties:
398|    """Property-based tests for PromptAssembler."""
399|    
400|    @given(
401|        system_prompt=st.text(min_size=0, max_size=1000),
402|        goal=st.text(min_size=0, max_size=500),
403|        query=st.text(min_size=0, max_size=500),
404|    )
405|    @settings(max_examples=100)
406|    def test_assemble_never_empty(self, system_prompt, goal, query):
407|        """Property: Assembled prompt is never empty."""
408|        assembler = PromptAssembler(session_budget=8000)
409|        prompt = assembler.assemble(
410|            system_prompt=system_prompt,
411|            goal=goal or None,
412|            recent_chunks=[],
413|            retrieved_chunks=[],
414|            query=query,
415|        )
416|        assert isinstance(prompt, str)
417|        assert len(prompt) > 0
418|    
419|    @given(text=st.text(min_size=1, max_size=10000))
420|    def test_estimate_tokens_positive(self, text):
421|        """Property: Token estimate is always positive for non-empty text."""
422|        assembler = PromptAssembler()
423|        tokens = assembler._estimate_tokens(text)
424|        assert tokens > 0
425|    
426|    @given(
427|        text1=st.text(min_size=1, max_size=1000),
428|        text2=st.text(min_size=1, max_size=1000),
429|    )
430|    def test_estimate_tokens_monotonic(self, text1, text2):
431|        """Property: Longer text produces more tokens."""
432|        assembler = PromptAssembler()
433|        combined = text1 + text2
434|        assert assembler._estimate_tokens(combined) >= assembler._estimate_tokens(text1)
435|    
436|    @given(
437|        chunk_type=st.sampled_from(["user_message", "tool_call", "result", "memory", "system"]),
438|        payload=st.dictionaries(
439|            keys=st.text(min_size=1, max_size=10),
440|            values=st.text(min_size=0, max_size=500),
441|        ),
442|    )
443|    def test_compress_chunk_never_exceeds_original(self, chunk_type, payload):
444|        """Property: Compressed chunk is never larger than original."""
445|        assembler = PromptAssembler()
446|        original = json.dumps({"type": chunk_type, "payload": payload})
447|        compressed = assembler._compress_chunk({"type": chunk_type, "payload": payload})
448|        assert len(compressed) <= len(original) + 50  # Small overhead for formatting
449|```
450|

501|## 8. Chaos Engineering
502|
503|### 8.1 What is Chaos Engineering for AI Agents
504|
505|Chaos engineering for AI agents involves **deliberately injecting failures** to validate that the agent recovers gracefully. Unlike traditional chaos engineering (which kills servers), agent chaos focuses on:
506|
507|- **LLM failures** — malformed responses, timeouts, rate limits, empty content
508|- **Tool failures** — crashes, timeouts, invalid outputs, permission errors
509|- **Context failures** — corrupted data, missing chunks, embedding failures
510|- **Database failures** — connection drops, pool exhaustion, slow queries
511|
512|### 8.2 ChaosLLM Taxonomy
513|
514|From [ChaosLLM (ISSRE 2025)](https://orbilu.uni.lu/bitstream/10993/67676/1/ISSRE2025_Iannillo.pdf), four classes of tool-level failures:
515|
516|| Failure Class | Description | AgentHarness Example |
517||---------------|-------------|---------------------|
518|| **Crash** | Tool raises exception | `read_file` on non-existent file |
519|| **Timeout** | Tool hangs | `terminal("sleep 1000")` |
520|| **Corruption** | Tool returns wrong data | `read_file` returns wrong file content |
521|| **Latency** | Tool is slow | `web_search` with 30s delay |
522|
523|### 8.3 Chaos Test Implementation
524|
525|```python
526|class TestAgentChaos:
527|    """Chaos engineering tests for AgentHarness."""
528|    
529|    async def test_agent_handles_malformed_tool_json(self):
530|        """Agent should not crash on invalid tool call JSON."""
531|        provider = AsyncMock()
532|        provider.complete = AsyncMock(return_value=LLMResponse(
533|            content="",
534|            tool_calls=[{
535|                "id": "call_1",
536|                "function": {"name": "read_file", "arguments": "not valid json{"},
537|            }],
538|        ))
539|        
540|        agent = ReActAgent(provider=provider, max_iterations=5)
541|        response = await agent.run(session_id, "test")
542|        
543|        # Should not crash — should return an error or retry
544|        assert response is not None
545|        assert response.iterations >= 1
546|    
547|    async def test_agent_handles_tool_timeout(self):
548|        """Agent should not hang when a tool times out."""
549|        # Register a tool that sleeps forever
550|        @registry.register()
551|        async def slow_tool():
552|            await asyncio.sleep(1000)
553|        
554|        provider = AsyncMock()
555|        provider.complete = AsyncMock(return_value=LLMResponse(
556|            content="",
557|            tool_calls=[{
558|                "id": "call_1",
559|                "function": {"name": "slow_tool", "arguments": "{}"},
560|            }],

688|## 9. Load Testing
689|
690|### 9.1 What Makes Agent Load Testing Different
691|
692|Traditional load testing assumes **stateless, deterministic** requests. AI agents violate both assumptions:
693|
694|- **Stateful** — conversations accumulate context, making each request heavier than the last
695|- **Non-deterministic** — LLM outputs vary, making response times unpredictable
696|- **Expensive** — every LLM call costs money, so load testing can be costly
697|- **Context-dependent** — performance degrades as context grows ("context avalanche")
698|
699|### 9.2 Load Testing Strategy for AgentHarness
700|
701|```python
702|import asyncio
703|import time
704|from statistics import mean, stdev
705|
706|class AgentLoadTest:
707|    """Load testing for AgentHarness."""
708|    
709|    async def run_concurrent_agents(self, num_agents: int, messages_per_agent: int):
710|        """Run multiple agents concurrently."""
711|        latencies = []
712|        errors = []
713|        
714|        async def run_agent(agent_id: int):
715|            provider = FakeProvider([...])  # Pre-configured responses
716|            agent = ReActAgent(provider=provider, max_iterations=5)
717|            
718|            for msg_num in range(messages_per_agent):
719|                start = time.monotonic()
720|                try:
721|                    response = await agent.run(
722|                        session_id=uuid.uuid4(),
723|                        user_message=f"Message {msg_num} from agent {agent_id}",
724|                    )
725|                    latency = time.monotonic() - start
726|                    latencies.append(latency)
727|                except Exception as e:
728|                    errors.append((agent_id, msg_num, str(e)))
729|        
730|        await asyncio.gather(*[
731|            run_agent(i) for i in range(num_agents)
732|        ])
733|        
734|        return {
735|            "total_requests": num_agents * messages_per_agent,
736|            "successful": len(latencies),
737|            "failed": len(errors),
738|            "mean_latency": mean(latencies) if latencies else 0,
739|            "p95_latency": sorted(latencies)[int(len(latencies) * 0.95)] if latencies else 0,
740|            "errors": errors,
741|        }
742|```
743|
744|### 9.3 Load Testing Scenarios
745|
746|| Scenario | Concurrency | Messages/Agent | Assertion |
747||----------|-------------|----------------|-----------|
748|| Baseline | 1 | 1 | Establishes baseline latency |
749|| Low load | 5 | 5 | Latency within 2x of baseline |
750|| Medium load | 20 | 10 | No errors, p95 < 30s |
751|| High load | 50 | 20 | Graceful degradation |
752|| Stress | 100 | 50 | System doesn't crash |
753|| Context avalanche | 10 | 100 | Context doesn't exceed budget |
754|
755|### 9.4 Load Testing Tools
756|
757|- **Locust** — Python-based, good for HTTP-level load testing
758|- **k6** — JavaScript-based, good for API load testing
759|- **Gatling** — Scala-based, high performance
760|- **Custom asyncio** — for agent-specific load testing (as shown above)

763|
764|AgentHarness has **zero load testing**. This is expected for an early-stage project but should be addressed before production deployment.
