21|## 1. LLM Usage Tracking and Cost Optimization
22|
23|### 1.1 Industry Landscape
24|
25|The LLM cost optimization market reached $863.7M in 2025 and is projected to hit $9.2B by 2035 (CAGR 26.7%). Model selection and routing alone capture 41.8% of this market. Key insight: **40–60% of enterprise LLM spend is pure waste** — redundant calls, over-specified models, no caching, and no budget controls.
26|
27|### 1.2 Usage Tracking Patterns
28|
29|**OpenRouter Analytics API** (2026) is the most complete reference implementation:
30|- Per-request usage automatically included in every API response (prompt tokens, completion tokens, reasoning tokens, cached tokens, cost)
31|- Analytics API with management keys for spend analysis grouped by model, API key, app, user, workspace
32|- Metrics: `total_usage`, `request_count`, `tokens_total`, `cache_hit_rate`, `blended_cost_per_mtok`
33|- Dimensions: model, API key, app, user, workspace, origin, country, data region, finish reason, context length, session
34|- Granularity: minute, hour, day, week, month
35|- Cost components: `usage_upstream` (raw inference), `usage_cache` (savings), `usage_data` (discounts), `usage_web`, `usage_file` (surcharges)
36|
37|**OpenRouter State of AI 2025** (100T token study):
38|- Weak price elasticity: 10% price decrease → only 0.5–0.7% usage increase
39|- Four usage-cost archetypes: Premium leaders (Claude Sonnet), Efficient giants (Gemini Flash, DeepSeek), Long tail (Qwen, Granite), Premium specialists (GPT-4/5 Pro)
40|- Key operator insight: **cost-per-successful-outcome** matters more than cost-per-token
41|
42|**LLMFlow** (open-source): Local observability proxy that tracks costs, tokens, latency for OpenAI, Anthropic, Gemini, Ollama. Uses OpenTelemetry for trace collection. SQLite backend keeps data local.
43|
44|**toolkit-cost-optimizer** (PyPI): Ingests gateway/trace/usage exports, prices every request by token class (input, cache reads/writes, output, reasoning), joins per-request quality scores, finds cheapest routing that keeps quality above a floor. Produces cost/quality Pareto frontier and LiteLLM proxy config.
45|
46|**AiFinOps** (open-source): Self-hosted OpenAI-compatible gateway for cost governance. Every call logged to Postgres before response returns. Provider/model allow-list gate. Cost attribution headers (tenant, application, module, user, transaction, region, environment).
47|
48|**Obol**: No-SDK cost tracking across 9 providers. $5/month flat. Forecasts month-end bill with exponential smoothing. MAD + CUSUM anomaly detection. Cache savings tracker.
49|
50|### 1.3 Cost Optimization Techniques
51|
52|| Technique | Typical Savings | Implementation Effort | Best For |
53||---|---|---|---|
54|| Prompt optimization | 20–40% | Low (hours) | Everyone, immediate wins |
55|| Response caching | 30–70% | Low-Medium (days) | Repetitive queries |
56|| Model routing | 40–60% | Medium (weeks) | Mixed complexity traffic |
57|| Batching | 20–50% | Medium (weeks) | High-volume, latency-tolerant |
58|| Prompt caching | 50–90% on cached | Low (hours) | Long system prompts, RAG |
59|| Self-hosting | 60–90% | High (months) | >1M queries/month |
60|
61|**RouteLLM** (ICLR 2025): Well-trained complexity router achieves 95% of GPT-4 performance while routing only 14–26% of requests to the expensive model — **75–85% cost reduction** on routed workloads.
62|
63|**Model routing approaches:**
64|- **Rule-based**: Simple but brittle; misroutes queries that break assumptions
65|- **Classifier-based**: Trains lightweight model to predict optimal LLM per query; approaches best-single-model performance at significantly lower cost
66|- **Cascading**: Starts with smallest model, escalates on low confidence; adds latency per escalation
67|- **Cache-aware routing**: Routes similar queries to same replica to maximize cache hit rates (3x P90 latency improvement)
68|
69|**Production pitfalls that kill routing systems:**
70|1. No structured logging of routing decisions → flying blind
71|2. No multi-provider fallback → single point of failure
72|3. Cold start on new query types → misclassification
73|4. Sequential cascade latency → worse than direct routing
74|5. Confidence miscalibration at the tail → errors on rare inputs
75|
76|**Multi-agent cost guardrails** (critical for AgentHarness):
77|- Rate limiting at agent level — hard cap on requests per unit time
78|- Real-time cost monitoring with automatic API key blocking on anomalous spend
79|- Budget-aware agent design — each agent knows its spend limit before escalating
80|- Cost kill-switch: soft warn at 70% of budget, hard halt at 100%
81|- Idempotent run IDs for safe retries
82|

203|## 3. Agent Evaluation and Testing
204|
205|### 3.1 Industry Landscape
206|
207|Agent evaluation has become its own discipline, distinct from LLM evaluation. Key insight: **you score trajectories — plan, tool calls, arguments, final answer — not just text.**
208|
209|**Four eval layers every production agent needs:**
210|
211|| Layer | What it tests | When it runs | Cost |
212||---|---|---|---|
213|| **Unit evals** | Individual components (tool call, classifier, extraction) | Every commit | Fast (<5s), cheap |
214|| **Trajectory evals** | Full agent on fixed dataset (50–200 real prompts) | Every PR | Medium |
215|| **Outcome evals** | Final output correctness (LLM-as-judge or ground truth) | Nightly | Expensive |
216|| **Online evals** | 1–5% live production traffic, async grading | Continuous | Ongoing |
217|
218|**Key evaluation frameworks:**
219|
220|- **DeepEval**: 50+ research-backed metrics, Pytest-style, CI/CD regression testing. `@observe` decorator captures component-level traces. `deepeval test run` works as Pytest plugin.
221|- **Braintrust**: Eval-first with CI/CD blocking, datasets, experiments. Native GitHub Action posts results to PRs and blocks merges. One-click production-to-eval conversion. Loop AI for automated scorer/dataset generation.
222|- **LangSmith**: Native LangChain integration, trajectory evaluators (deterministic match + LLM-as-judge), annotation queues, online evals.
223|- **Langfuse**: OSS, self-hosted, programmatic dataset runs.
224|- **Promptfoo**: Config-as-code, YAML/JSON, security testing.
225|
226|**Trajectory evaluation metrics:**
227|- **TrajectoryAccuracy**: How closely agent's step sequence matches golden path
228|- **ToolCallAccuracy**: Was the right tool called with the right arguments?
229|- **TrajectoryEfficiency**: Was the path the shortest one that worked?
230|- **PlanQuality**: Did the agent decide on a sensible sequence before acting?
231|- **PlanAdherence**: Did the agent stick to its plan?
232|- **StepEfficiency**: Did the agent finish in reasonable steps without redundant retries?
233|
234|**Statistical pass/fail for non-deterministic agents:**
235|- Define thresholds on aggregate scores, not individual assertions
236|- Use `num_repetitions` to average out single-run noise
237|- Compare against named baseline, not absolute thresholds
238|- Gate on dimensions separately (safety, correctness, relevance)
239|
240|**Production-to-eval flywheel:**
241|1. Production failure captured as trace
242|2. Trace's tool inputs/outputs recorded
243|3. Agent re-run against frozen tool responses (deterministic regression test)
244|4. Failed trace added to regression dataset
245|5. Eval suite grows stronger with every production incident
246|
247|**Sierra's tau-bench** introduced `pass^k` reliability metric: decays exponentially, exposes gap between "sometimes works" and "reliably works."
248|
249|**AgentAssay** (arXiv 2603.02601): Sampling-based approaches for statistical confidence without exhaustive re-evaluation.
250|
251|### 3.2 Recommendations for AgentHarness
252|
253|**Current state:** AgentHarness has `skills/testing-qa/` and `docs/research-testing.md` with LoCoMo evidence retrieval, memory-policy training, and identity-drift evaluations (`ah/research/`), but no CI eval gate.
254|
255|**Priority actions:**
256|
257|1. **Build unit eval layer** (Week 1–2)
258|   - Test individual tools, classifiers, extraction prompts
259|   - Fast (<5s), runs on every commit
260|   - Block merges on regressions
261|
262|2. **Build trajectory eval layer** (Week 3–6)
263|   - Curate 50–200 representative tasks with known-good trajectories
264|   - Implement trajectory evaluators: deterministic match + LLM-as-judge
265|   - Run on every PR, block merge if trajectory score drops below threshold
266|   - Use statistical thresholds (aggregate averages, not individual assertions)
267|
268|3. **Build outcome eval layer** (Week 7–8)

287|## 4. Agent Security Patterns
288|
289|### 4.1 Threat Landscape
290|
291|**EchoLeak (CVE-2025-32711)**: Zero-click indirect prompt injection in Microsoft 365 Copilot. Exfiltrated internal documents from a single crafted email. CVSS 9.3. Every enterprise rebuilt their agent threat model after this.
292|
293|**OWASP Top 10 for Agentic Applications** (December 2025):
294|- Prompt injection holds the top spot
295|- New categories: System Prompt Leakage, Vector and Embedding Weaknesses
296|- Excessive Agency rewritten for tool-using agents
297|
298|**Attack statistics (2025–2026):**
299|- Indirect prompt injection: 55% of all observed agent attacks
300|- Multi-hop attacks growing 70% year over year
301|- 62% of successful enterprise exploits pass through injected document/email/tool output
302|- AgentDojo: 97 realistic tasks, 629 security test cases
303|- InjecAgent: ReAct-prompted GPT-4 vulnerable to indirect prompt injection 24% of the time
304|- AgentVigil: 71% success on AgentDojo, 70% on VWA-adv against o3-mini and GPT-4o
305|
306|**Real-world CVEs:**
307|- CVE-2025-32711 (EchoLeak): M365 Copilot zero-click exfiltration
308|- CVE-2025-53355: MCP server indirect prompt injection → arbitrary command execution
309|- CVE-2025-54073: MCP server command execution
310|- Antigravity sandbox escape: `find_by_name` tool `-X` flag injection → arbitrary code execution
311|
312|### 4.2 Security Patterns
313|
314|**Design patterns for securing LLM agents** (arXiv 2506.08837):
315|
316|1. **Input/output detection systems**: Heuristic/AI-based filters for prompt injection attempts. Raise the bar but cannot guarantee prevention.
317|
318|2. **Isolation mechanisms**: Constrain agent capabilities when handling untrusted input. Predefined tool sets, system controller disables all others.
319|
320|3. **System-level isolation**: Sandboxing, capability control, information-flow labels.
321|
322|**Production security architecture** (from Sandboxing and Capability Control paper):
323|
324|- **Policy-enforced tool brokers**: All tool calls pass through a policy engine
325|- **Object-capability grants**: Fine-grained permissions per tool, per resource
326|- **Information-flow labels**: Track data sensitivity through the system
327|- **Isolated execution sandboxes**: Code execution in containers with no network access
328|- **Scoped identities**: Per-tool credentials with minimal permissions
329|- **Egress control**: Network egress filtering
330|- **Approval gates**: Human-in-the-loop for high-risk actions
331|- **Adversarial evaluation**: Treat agent as compromised until proven otherwise
332|
333|**Scoped permissions and sandboxing** (OWASP ASI03, ASI05):
334|- Scoped credentials for every tool
335|- Isolated runtime for code execution
336|- Blast radius capping: what can the agent physically reach if it decides to act?
337|
338|**Multi-agent security:**
339|- Cross-agent manipulation is an emerging threat
340|- Trust boundaries between agents must be explicit
341|- Agent-to-agent communication needs authentication and authorization
342|

382|## 5. Agent Configuration and Skill Systems
383|
384|### 5.1 Industry Landscape
385|
386|**AGENTS.md** has emerged as the de facto standard for project-level agent instructions:
387|- Open standard, tool-agnostic
388|- Root of repository, loaded at session start
389|- Converts generic agent into project-aware agent
390|- Keep to ~100 lines as pointer map; knowledge lives in `docs/`
391|- Nested AGENTS.md files for subprojects (closest takes precedence)
392|- Codex: root-down concatenation, `AGENTS.override.md` for replacements, 32 KiB combined limit
393|- Claude Code: cwd-up walk, `CLAUDE.md` with `@AGENTS.md` reference
394|
395|**Agent configuration as managed supply chain** (arXiv 2606.26924):
396|- 10,008 public GitHub repos studied; 6,145 agent config files found
397|- 10.1% exact-duplicate rate (cross-org)
398|- 75.5% of clone pairs cross organizational boundaries
399|- 58% single-commit; 0.4 commits/month (vs 0.6 for comparator files)
400|- <1% declare permission boundaries (vs 33% for GitHub Actions workflows)
401|- Four control-plane mechanisms: content addressing, permission declaration, state-machine promotion, drift detection
402|
403|**SoulSpec v0.5** (open standard for agent personas):
404|- `soul.json` manifest + `SOUL.md` personality + `AGENTS.md` workflows + `STYLE.md` + `HEARTBEAT.md`
405|- Three-level progressive disclosure: Level 1 (quick scan: `soul.json` only), Level 2 (full read: `SOUL.md` + `IDENTITY.md`), Level 3 (deep dive: `AGENTS.md`, `STYLE.md`, `HEARTBEAT.md`, examples)
406|- `allowedTools` for tool transparency
407|- `recommendedSkills` with version constraints and required/optional flags
408|- `compatibility.frameworks` for multi-framework support
409|- SoulScan: checks for prompt injection, secret leaks, 50+ patterns
410|
411|**Claude Agent Skills** (Anthropic, open standard):
412|- Directory with `SKILL.md` (YAML frontmatter: `name`, `description`)
413|- Progressive disclosure: name+description in system prompt, full body loaded on demand
414|- Additional files (scripts, references) loaded as needed
415|- Code execution environment with filesystem access, bash, pre-installed packages
416|- No network access, no runtime package installation
417|- Skills vs AGENTS.md: AGENTS.md = project orientation, Skills = task knowledge
418|
419|**Production system prompt architecture** (from 102K-char production prompt analysis):
420|- XML-tagged concern isolation (~25 named sections)
421|- Temporal grounding at head (cache-stable)
422|- Static tool definitions with runtime masking
423|- Skills as pointers (not inlined content)
424|- Discrete safety/compliance blocks
425|- Runtime parameters at tail (cache-optimal)
426|- Cache stability: any change to earlier token invalidates all cached content
427|

430|**Layered instruction scopes:**
431|- Global defaults → project-level files → directory overrides
432|- Most specific rule always wins
433|- `AGENTS.override.md` for temporary replacements
434|
435|**Prompt governance:**
436|- Store as plain markdown in git
437|- PRs for behavior changes
438|- Content-addressed pinning (SHA-256)
