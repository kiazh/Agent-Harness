## 1. Root cause (one sentence each)

- **R4-040:** `refresh` captured its generation *after* the caller's tokens had
  been loaded outside the lock; when the store had already been removed by a
  logout, the reread found `stored is None`, both publish gates compared only
  against post-logout state (generation taken at entry, snapshot taken at
  entry), so a successful exchange recreated the removed store.
- **R4-041:** `exchange_code`'s publish gate treated *any* store-fingerprint
  change as cancellation (`:804-815`), so a benign peer refresh rotating the
  store while the login exchange was in flight raised
  `chatgpt_auth_cancelled` after the single-use authorization code had already
  been spent by the successful exchange.
- **R4-049 (shared + chatgpt):** `store_lock` / chatgpt `_store_lock` used
  blocking `flock(LOCK_EX)` with no bound, so a wedged (or very slow) peer held
  every waiter — including logout — forever.

## 2. Fix

- `machina/security/store_fence.py`
  - `store_lock` acquires non-blocking (`LOCK_NB` / `LK_NBLCK`) in a 50 ms
    poll loop bounded by `STORE_LOCK_TIMEOUT_SECONDS = 45.0` (one full token
    round trip — ≤10 s connect + 20 s read — plus headroom, since refreshes
    hold the lock across the HTTP call) and raises the new typed
    `StoreLockTimeout(TimeoutError)` naming only the lock file; the fd is
    always closed and the yield/unlock path is unchanged. No new API beyond the
    constant + typed error; store formats, modes, generation, and fingerprint
    semantics untouched.
- `machina/security/chatgpt_auth.py`
  - `_store_lock` now delegates to `store_fence.store_lock` (deletes the
    duplicated platform flock code) and translates the capped wait into the
    store's typed contract: `ChatGPTAuthError(code="chatgpt_auth_lock_timeout")`.
  - `refresh` refuses, *before* the network call, when caller-supplied tokens
    meet an absent store (`stored is None`) — `chatgpt_auth_signed_out`
    ("auth-required") — so a pair loaded before a logout can never recreate the
    store or replay the stale rotating token. `tokens=None` + absent store keeps
    the existing `chatgpt_auth_missing`.
  - `exchange_code` now cancels only on a generation change or on the store
    having been *removed* out from under the exchange (snapshot present → now
    absent; indistinguishable from a revocation, and pinned by the existing
    `test_exchange_code_refuses_to_clobber_a_store_that_changed`). A content
    change with no generation bump — a peer rotation — publishes the exchanged
    pair (the code is already spent and the fresh login pair is the newest
    credential). Shared message factored into `_cancelled_error()`.
- `tests/test_chatgpt_auth_adversarial.py` (new, 297 lines): real store files,
  real cross-process `flock` held by a child process, HTTP mocked only at the
  `httpx.MockTransport` boundary via the modules' `client=` seam; the only
  patched value is the documented lock-timeout constant (shortened to 0.4 s).

## 5. Residual risks

1. **Sibling surfaces raise the shared typed error.** `claude_auth` /
   `gemini_auth` / `copilot_auth` call `store_fence.store_lock` directly, so a
   >45 s contention now surfaces `store_fence.StoreLockTimeout` (a
   `TimeoutError`), not their provider-typed errors. Their lane can translate
   it; no behavior change for legitimate contention (< one round trip).
2. **chatgpt `logout` still takes the (now bounded) lock.** Under pathological
   contention it can raise `chatgpt_auth_lock_timeout` after 45 s, and
   `cli/auth.py` / the gateway catch only `OSError` around logout — a typed
   traceback is possible in that extreme edge (previously: unbounded block).
   Switching chatgpt logout to the siblings' lock-free `fenced_logout` (plus a
   post-save generation recheck in `refresh`) is the natural follow-up, kept
   out of this change to stay scoped.
3. **Publish-over-rotation is intentional.** The login pair overwrites the
   peer's rotated content when generations match; the peer's in-memory pair
   stays valid until expiry and its next refresh naturally re-adopts/re-rotates.
4. **Lock spelling now resolved.** `_store_lock` previously opened
   `<raw target>.lock`; it now uses `store_fence._store_target` (resolved),
   matching the generation files. A long-lived process holding a lock under the
   old spelling across a live upgrade would momentarily not exclude — an
   upgrade-window-only concern.
5. **Generation/fingerprint helpers remain duplicated** inside
   `chatgpt_auth` (only the lock was unified with `store_fence`); dedup is a
   follow-up (R4-096 family), not needed for these fixes.
6. **Windows path not exercised here**: the bounded loop uses
   `msvcrt.LK_NBLCK` + the same poll loop (branch marked `pragma: no cover` as
   before); POSIX flock evidence only on this machine.
7. **R4-049 chmod fd-close helper not in this lane** (explicitly out of the
   assigned scope): chatgpt's two `mkstemp` sites (`save_tokens`,
   `invalidate_credentials`) still chmod via path; leave-to-owner.
