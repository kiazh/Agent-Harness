## Root causes (one sentence each)

1. **R4-060:** `git grep` was whitelisted as a routine git read (`commands.py` `_GIT_COMMANDS`)
   and the policy traversal classifier (`_recursive_traversal`) knew only `grep`/`rg`/`find`,
   so `git grep --untracked --no-exclude-standard TOKEN` walked ignored files (`.env`)
   without the review that plain `grep -R`/`rg` walks already require, while
   `sensitive_path` matched path components literally — a `REV:path` operand
   (`HEAD:credentials`) never matched `credentials`, and backup spellings
   (`credentials~`, `.env-backup`, `.netrc.bak`) never matched their family.
2. **R4-061:** the escape-arg check tested every argv token against a flat `_ESCAPE_ARGS`
   set containing bare `-c`/`-C`/`-o`, so benign format selectors (`wc -c`, `ls -C`,
   `ls -o`, `grep -C 2`, `head -c 100`, `diff -c`) were pushed to review while the same
   letters mean config/code/boolean-OR redirects for `git`/`python`/`find`.
3. **R4-062:** `_tree_contains_component` swallowed `OSError` from `iterdir()` and entry
   stat (`continue`) while the entry-cap truncation returned `True` (fail closed), so an
   unreadable subdirectory made the copy scan report "clean" and the recursive copy was
   allowed.

| Task | Implementation |

## Residual risks (explicit)

1. **Retained over-block outside the listed calibration set (fail-closed noise, not a
   hole):** `rg -C 2`, `ls -c`, `wc -C`, `git grep -c` and `uv run wc -c` (the outer escape
   check runs before the `uv run` recursion) still require review. `git grep -f patterns.txt
   README.md` also stays review because the pre-existing generic git force-flag guard
   (`{"--amend","--force","-f"}`) applies to every git subcommand; relaxing that is outside
   R4-060/061.
2. **Git pathspec grammar is handled conservatively, not parsed:** any `:`, `!`, `(` prefix
   or `*?[` magic routes to review; unknown/exotic forms (`:(attr:…)`, `--and` combinations)
   therefore never classify routine. Plain names are checked with filesystem `is_dir()`;
   git resolves plain pathspecs the same way.
3. **Revspec split is on the first colon** with Windows drive prefixes excluded; revisions
   cannot contain `:` in git syntax. `sensitive_path` only escalates.
4. **Backup stripping can over-match** a deliberately named `credentials.1`/`id_rsa.bak`
   outside credential use — by design (fail closed).
5. **R4-062 scope:** the cited `iterdir`/entry-stat sites now fail closed; the
   `_recursive_copy_sources` root-operand `is_dir()` except-path still `continue`s on an
   exotic `OSError` (pre-existing, outside the cited lines), and `_tree_contains_component`
   keeps its fast `not root.is_dir()` return.
6. **`-O` detection** treats any uppercase `O` in a short cluster as pager execution; no
   other `git grep` option uses `O`.
7. **Shared working tree:** `machina/permissions/broker.py` was modified by a concurrent
   task (R4-065–067 group) during this work; I did not touch it. All captures above were
   green at their recorded time.
8. No commit was made (per task rules); no new dependencies; only the two policy files,
   the test file, and the proof artifacts are attributable to this task.
