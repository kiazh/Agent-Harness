## Allowlist widening — GREEN

Root cause (D1 probe, still RED at this lane's start): `secrets.set`
refused `OPENCODE_API_KEY` / `CUSTOM_API_KEY` / `CUSTOM_BASE_URL` /
`KIMI_API_KEY` ("not a managed secret key") while `provider/specs.py`
consumes the first two as `api_key_env`, `provider/factory.py` consumes
`CUSTOM_BASE_URL`/`CUSTOM_API_KEY`, and `config.SECRET_KEYS` /
`LEGACY_ENV_VARS` carry all of them — unsettable from any gateway/UI
surface (`config.set` refuses secrets, `secrets.set` refused the names).

Fix (single-source, no duplicated list): `PROVIDER_KEYS` += the three API
keys (`env_file.py`); `MANAGED_ENV_KEYS` += `CUSTOM_BASE_URL`
(`gateway/features/secrets.py`, whose `_ALLOWED_SECRET_KEYS` derives from
both tuples — no other gateway change needed); `KNOWN_KEYS` += all four
(`ui/src/features/keys.ts`). `OPENCODE_BASE_URL` deliberately left out:
it is a non-secret already settable via `config.set` (in `DEFAULTS`), and
it was not in the RED probe. `machina setup` automatically offers the
three new keys (it iterates `PROVIDER_KEYS`).

Proof: `test_r4_093_cli_allowlist.py` drives the real `secrets_set` /
`secrets_clear` / `secrets_list` handlers with a real tmp `.env`:
set → env + `.env` carry the value; clear → env popped; catalog lists all
four; specs/config wiring pinned; control-plane keys (`PATH`,
`MACHINA_GATEWAY_TOKEN`) still refused; a source-parity test asserts
`keys.ts` carries every Python-side key. RED on unfixed: 7/9 fail with
`INVALID_PARAMS "not a managed secret key"` (the 2 passing are the
control-plane-refusal and specs-wiring pins, which hold pre- and post-fix
by design).

## CLI cluster — GREEN (6/6 + escaping)

- **config-set/mode sync `.env`+env like gateway.** Root cause: the
  gateway's `config.set` syncs `MACHINA_MODEL`/`MACHINA_PROVIDER` to the
  process env + `.env` (else `Config.get`'s env-first precedence shadows or
  resurrects defaults across restarts); the CLI never synced. Fix: new
  `_sync_env_shadow()` in `cli/__init__.py` mirroring the gateway
  (env set + best-effort `.env` write, warn-only on failure), called on
  persisted `config-set model|provider` and on every persistent
  `machina mode` set/revoke (`MACHINA_EXECUTION_MODE` has the same
  shadowing hazard). Non-shadowed keys (e.g. `theme`) write no env line
  (pinned by test). **Behavior change:** `machina mode X` now appends
  `MACHINA_EXECUTION_MODE=X` to `.env` when absent (gateway already does
  this for `MACHINA_MODEL`/`MACHINA_PROVIDER`); `config.set` validation
  failures are now typed `output.error` + exit 1 instead of a traceback.
- **Rich escaping.** Root cause: `output.*` helpers interpolated raw user
  text into Rich markup — a `[/b]` in a title raises `MarkupError`
  (probed: crashes table rendering and direct prints). Fix: `output.py`
  escapes all message/label/value/cell inputs (single authoritative
  impl); redundant pre-`escape()`s at `cli/*` call sites into `output.*`
  removed (double-escape would print literal backslashes); direct
  `console.print` interpolations of user-controlled data across
  `__init__.py` / `providers.py` / `interop.py` escaped at the site.
  **Behavior change:** `fork`/`delete`/`context` invalid-ID, hub
  publish/install failures and curator/hub unknown-action now render via
  `output.error` (`✗` prefix) instead of raw `[red]...[/red]`.
- **Traceback-free fork/growth.** `fork` maps the store's `ValueError`
  (e.g. unknown session) and `OSError` to exit 1 + message; growth
  `_execute` additionally maps `OSError`, and `import-policy` reads/parses
  its file inside the guarded operation (previously `json.loads` ran
  before any guard → bare traceback). Growth messages now carry an
  `Error:` prefix.
- **`providers models --refresh` keeps the cache on empty success.** Root
  cause: `models = save(...) if pulled else []` discarded the cached list
  from the display (and exited 1) when a live fetch succeeded with zero
  models. Fix: empty success keeps and shows the cached list with a
  "showing the cached list" warning, exit 0; the store is never
  overwritten with empty. Non-empty refresh still replaces (pinned).
- **setup env-file guard.** Bad `$MACHINA_ENV_FILE` and `.env` seed/write
  failures are typed exit-1 errors, never tracebacks. The committed
  `machina init` recovery message (`Run machina init and retry.`) is
  untouched.
- **repl `--mode` validation.** `repl` passed `--mode` straight to the
  launcher (invalid values silently ignored); now validated (and applied)
  exactly like the `main`/`chat` paths, exit 1 otherwise.

RED on unfixed: 12/18 cluster tests fail for exactly the named reasons
(MMarkupError on helpers/tables, missing env/`.env` sync, unvalidated
repl mode reaching the UI launcher, empty-refresh exit 1 with no cached
rows, tracebacks-as-exceptions on fork/growth/setup/config-set paths).
The 6 passing-on-unfixed are pre-existing-correct regression guards
(mode invalid, fork invalid UUID, delete/`config-set theme` markup,
non-empty refresh, non-shadowed key).
