# R4-010 — SSE spurious error frame — evidence

## Before (harness RED, documented by H-SSE)
- `tests/test_sse_stream_adversarial.py` (pre-fix): 2 passed, 1 xfailed (strict).
- Frames on a multi-event stream: `['turn.started','text','text','text','token_usage','error','done']`.
- Logged chain: `streaming.py:177 → _owned_step (:85) → turn_engine.py:320 → agent.py:131 → session_mode.py:93 end_turn_scope → :105 _turn_scope.reset(token) → ValueError: ... was created in a different Context`.
- The repo's own E2E proof corroborates: `"error": 1` on every SSE turn
  (`docs/verification/proofs/2026-10-14-e2e-gate.md:231-277`).

## Root cause
Two distinct defects from one mechanism:
1. The stream wrapper (`instrument_stream`) entered/left the turn-mode ContextVar inside
   an async generator pulled by per-step tasks — token created in step-1's context, reset
   in another step's context → `ValueError`, surfaced as an error frame.
2. Because asyncio Tasks copy the creator's context, the scope was invisible to steps 2+
   anyway (mode cache silently degraded after step 1).

Separately, exercising the cancel path showed Starlette may **close** the response
generator from a different task context — so any cross-context teardown must be tolerant,
not merely relocated.

## Fix (driver-owned scope, per `TurnEngine.stream`'s documented contract)
- `machina/core/agent.py` — removed the ContextVar lifecycle from `instrument_stream`; the
  wrapper no longer enters/leaves the scope.
- `machina/api/routes/streaming.py` — driver enters `begin_turn_scope()` before the drive
  loop (so every `_owned_step` task copies it) and ends it in `finally`.
- `machina/gateway/server.py` — same pairing around the stdio driver loop (guarded reset).
- `machina/cli/__init__.py` — same pairing around the CLI chat drive loop (guarded reset).
- `machina/core/session_mode.py` — `end_turn_scope` is now tolerant of a foreign-context
  reset (async-generator close); the original context is tearing down in that case.
- `machina/api/routes/streaming.py` — same-class hardening of `resume_approval_var.reset`
  in the SSE finally (a latent copy of the bug: on a cancelled *resumed* stream it could
  abort claim cleanup before engine.close).
- `tests/test_sse_stream_adversarial.py` — R4-010 xfail marker removed (now a hard pass).

## After (verified)
- `tests/test_sse_stream_adversarial.py` — 3 passed (no `error` frame; no cross-context
  ValueError; cancel path still releases the claim and closes the provider).
- Focused set: `test_sse_stream_adversarial + turnscope_cache + api + production_smoke +
  trace_hierarchy + gateway + cli_turn_ownership + a5_turn_flow + architecture_layers +
  architecture_pairs + leaf_independence + config_import_cycle + wiring_parity`
  → **221 passed** (DB: `machina_test`).
- `ruff format --check` + `ruff check` on all touched files → clean.
