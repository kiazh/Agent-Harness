## R4-045 — `MACHINA_OAUTH_ALLOW_PLAINTEXT_KEYRING` inverted + allowlist bypass

**Root cause.** In `_keyring_backend_usable`, the flag branch
(`return "plaintext" not in lowered`) came *before* the plaintext check and
returned `True` for every non-plaintext backend — so with the flag set the
documented plaintext backend was rejected while unknown backends were
accepted without consulting `_ALLOWED_BACKENDS`.

**Fix.** The flag now gates only the plaintext/plain branch; every other
backend falls through to the unchanged strict allowlist (fail/null first).

**RED (unfixed, `R4-045_047_049_red_pytest.txt`).** The matrix failed in
both directions for exactly the named reason:

```
test_keyring_backend_policy_matrix[plaintext-flag-on-allowed]
  → OAuthKeyUnavailable: no secure OS keyring backend available ... (:113)
test_keyring_backend_policy_matrix[unknown-flag-on-rejected]
  → Failed: DID NOT RAISE OAuthKeyUnavailable
```

**GREEN.** Matrix row `plaintext-flag-on-allowed` and
`unknown-flag-on-rejected` pass together with the regression rows: native
backends allowed with and without the flag; `fail`/`null` rejected in both
states; `0`/`true` values do not enable the hatch (only the documented
`"1"`). The fake keyring module is a boundary stub; the real
`get_master_key()` path (bounded worker, read, create, `_write_new_key`) is
exercised, no live keyring access.

## R4-047 — bearer keys over non-loopback plaintext `http://`

**Root cause.** `_validate_base_url` accepted any `http(s)` scheme; a
non-loopback `http://` endpoint was stored and `add_provider` then wrote the
key to `.env`/`os.environ`, with `fetch_models` sending
`Authorization: Bearer` in cleartext.

**Fix.** New `_require_plaintext_allowed` (shared guard):

* loopback targets (`127.0.0.1`, `localhost`, `::1`, `0.0.0.0`) unchanged;
* non-loopback `http://` refused by default with a message naming the host
  and `MACHINA_ALLOW_PLAINTEXT_HTTP` (storing is refused before any key
  write; `fetch_models` also refuses, so hand-edited/pre-fix store entries
  cannot leak either);
* `MACHINA_ALLOW_PLAINTEXT_HTTP=1` (exact value only) opts in and logs a
  visible `WARNING` naming the host and the flag every time it applies;
* `https://` unaffected.

**RED (unfixed).**

```
test_non_loopback_plaintext_http_refused_by_default → DID NOT RAISE ProviderStoreError
test_opt_in_allows_non_loopback_http_with_visible_warning → AssertionError: []  (no warning)
test_opt_in_flag_must_be_exactly_one → DID NOT RAISE ProviderStoreError
test_fetch_models_refuses_plaintext_bearer_to_non_loopback_by_default → DID NOT RAISE
```

**GREEN.** Loopback `http://` (IPv4/localhost/`[::1]`) still stores. The
refusal path proves no store file, no `.env` line, and no live process key.
The opt-in path stores + warns (caplog, logger
`machina.security.providers`), and the network-boundary check
(`httpx.MockTransport`) observes `http` + `Authorization: Bearer
sk-cleartext` only in the opted-in case — in the default case the mock
handler is never invoked (`requests == []`).

## R4-049 (providers portion) — unbounded store lock

**Root cause.** `_store_lock` called blocking `fcntl.flock(fd, LOCK_EX)`;
any peer holding the lock (wedged or long-running) blocked every store
operation forever.

**Fix.** `_acquire_lock` — the repo's existing bounded idiom
(`connectors/oauth_store._file_lock_acquire`, `oauth_keys._acquire_creation_lock`):
`LOCK_EX | LOCK_NB`, `deadline = monotonic() + timeout`, 10 ms retry,
`_STORE_LOCK_TIMEOUT_SECONDS = 5.0`. On expiry the context manager raises
typed `ProviderStoreLockTimeout(ProviderStoreError)` (message names the
bound) and the `finally` path still closes the descriptor.

**Adversarial proof.** A child process takes the real cross-process
`flock` on `<store>.lock`; another child then runs the real
`store.add_provider` against the contended store:

```
override=0.4 {"error": {"type": "ProviderStoreLockTimeout", "message": "provider store lock timed out after 0.4s; another process holds it"}, "elapsed": 0.412, "leaked_fds": []}
override=0 {"error": {"type": "ProviderStoreLockTimeout", "message": "provider store lock timed out after 5s; another process holds it"}, "elapsed": 5.006, "leaked_fds": []}
{"store_file_created": false}
```

(`R4-045_047_049_lock_probe_green.txt`; `leaked_fds` compares `/dev/fd`
before/after.) The pytest adversary repeats the compressed-clock scenario
**5 times** (all typed error, elapsed < 3 s, no leaked fd) plus one run
under the production 5 s default (bound observed: `4.0 <= elapsed < 8.0`),
then asserts the store was never written. The adversary test was executed
**6 times** in total (3 full-suite runs + 3 targeted reruns): 30/30
compressed repeats and 6/6 production-bound runs green, 0 flake. Against
the unfixed code the same harness fails exactly on the block:

```
subprocess.TimeoutExpired: ... timed out after 10.0 seconds
Failed: lock acquisition blocked past the 10.0s harness window:
        the provider-store lock is unbounded
```

**Shape contract for the chatgpt-side twin (R4-049, other owner):** module
constant for the bound, non-blocking acquire loop with a monotonic
deadline, typed `*LockTimeout` error, descriptor closed on the failure
path. Note the chatgpt bound must exceed the holder's network critical
section (their lock spans a refresh round trip), unlike the providers lock
which only spans local JSON I/O.

## Residual risks / notes

1. **Not in this scoped portion:** `providers._save_store` still has the
   pre-existing chmod-before-fdopen fd leak (R4-049's "6 sites" helper
   belongs to the chmod-helper owner). Flagged for the R4-049 umbrella.
2. `_acquire_lock` catches `OSError` broadly (matching the two existing
   repo bounded-lock idioms); a non-contention errno (e.g. `ENOTSUP`) would
   be retried to the bound and reported as `ProviderStoreLockTimeout`
   rather than surfaced verbatim. Deliberate consistency trade-off.
3. Pre-existing store entries with non-loopback plaintext `http://` now
   fail model fetches unless opted in (intended fail-closed). Their chat
   path (`DirectProvider`, `core/provider/`) is owned elsewhere and
   unchanged here.
4. Windows branch of the bounded acquire is `# pragma: no cover`
   (`msvcrt.LK_NBLCK`), same as the existing platform branches; the POSIX
   adversary is the exercised path.
