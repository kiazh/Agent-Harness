## R4-081 — MCP chat child resolves a different DB than the parent's tools

**Probe:** the MCP `machina_chat` child ran with `sanitized_env(None)`, which
drops `DATABASE_URL`/`MACHINA_ENV_FILE`, so the child re-resolved its database
on its own while `machina_session_create`/`machina_status` used the parent's
already-resolved singleton.

**Root cause:** no DSN handoff across the parent→child boundary; the child
guessed from its own environment.

**Fix (owner decision: parent-resolves):** the parent resolves the DSN it
already uses (`machina.db.connection.db.dsn` — the same value the in-process
tools connect through) and hands it to the child as an explicit environment
override on the `_run_process` call (`env_extra` merged onto the sanitized
allowlist). Resolution failure fails closed (`status: failed`, class name only
— never values/messages) instead of spawning a guessing child. Secrets stay
out of logs: the DSN travels only in the child env, never in output/diagnostics.

**Files:**
- `machina/mcp_server/__init__.py`: `_child_database_env()` (parent-resolved
  `{"DATABASE_URL": dsn}` or `{}` when unresolved); `_run_process(..., env_extra)`
  merges the override; `machina_chat` resolves before spawn, fails closed on error.

**Proof (E2E, H-DB + real stdio server + real `machina chat` child):**
- New `test_chat_child_observes_the_parent_database[env, env_file]`
  (`tests/test_mcp_server.py`): real stdio server with exactly ONE DSN source
  (`DATABASE_URL` env, separately `MACHINA_ENV_FILE`); parent
  `machina_session_create` writes the row; the real chat child resumes it.
  The session pins an unknown provider so the child fails deterministically at
  the provider stage (no network/keys) — reaching that stage proves the row
  was read from the parent's database.
- RED (unfixed): both params fail — child exits `Session <id> not found`
  (`R4-081_084_red_mcp.txt`).
- GREEN (fixed): both pass.
- Supplements: `_child_database_env` pin (exact override / empty override /
  fail-closed without spawn), `env_extra` merge pin with a real child.

## R4-084 — REST SSE frames carried the claim token as `turnId`

**Probe:** `_stream_session` put the internal ownership claim token
(`turn:<id>:<nonce>` from `try_begin_turn`) on the wire as `turnId` in
`turn.started`, v2 envelopes via `canonical_http_event`, `approval.resumed`,
`turn.ownership_lost`, and `turn.cleanup_pending`.

**Root cause:** the route reused the owner token where the wire id belongs;
the stdio gateway keeps a canonical 12-hex id (`uuid4().hex[:12]`) separate
from the token.

**Fix:** the route mints the canonical id itself (`uuid.uuid4().hex[:12]`,
same shape as `gateway/server.py`), passes it as `turn_id=` to
`try_begin_turn` (whose token stays `turn:<id>:<nonce>` internally), and emits
the canonical id in every frame (turn.started, deltas' v2 envelopes,
approval.resumed, ownership_lost, cleanup_pending, terminal `done`/`message.complete`
via the shared envelope path). The claim token never leaves the module.
Protocol v1/v2 wrapping intact (`canonical_http_event`, serializers untouched);
`needs_approval`/`approval.resolved` shapes unchanged.

**Files:**
- `machina/api/routes/streaming.py`: canonical `turn_id` minted at claim time;
  all wire `turnId` sites switched from `turn_token` to `turn_id`; token still
  drives `TurnSpec.token`, renewal, and release.

**Proof (E2E, H-SSE — real route + real TurnEngine + real test DB, provider
faked at the factory boundary only):**
- `tests/test_sse_stream_adversarial.py`: v1 stream, v2 stream (every frame
  `validate_event`), live-claim capture from the DB mid-stream (wire id equals
  the claim's canonical component, claim spelling absent), real claim-steal
  (loss + cleanup frames keep the canonical id). All assert the 12-hex shape
  and scan every frame string for the `turn:<hex>:<nonce>` spelling.
- `tests/test_http_approval_resume.py::test_resume_frames_carry_canonical_turn_ids`:
  durable origin turn is canonical; resume `turn.started` and
  `approval.resumed` share the new id; `originTurnId` matches the record.
- RED (unfixed): all 4 new SSE tests fail with `turnId='turn:<…>:<…>'`
  (`R4-081_084_red_sse.txt`). GREEN (fixed): all pass.
